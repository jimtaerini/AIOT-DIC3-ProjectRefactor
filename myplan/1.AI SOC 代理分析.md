## 第一部分：依《期末專題提案作業規範》全面解析

本專題完全落實規範中對 **Domain AI Agent** 的核心定位：「**結合 AI Agent + Domain Knowledge + Data Analytics + Real-World Application，具備特定專業能力且非單純 Chatbot**」2, 3。

### 1. Abstract 摘要（A–F 六段式故事軸落實）6-12

- **A. Attention Getter**（動機與引題）：引用 2025 年國安局報告（中共對我國關鍵基礎設施侵擾日均 263 萬次 42, 46, 63）與 IBM 2026 年數據（全球資料外洩平均成本達 499 萬美元、平均調查週期 247 天 42, 46, 54），強調資安維運中心（SOC）告警處置速度直接決定損害大小 42, 46, 54。
- **B. But**（挑戰與 **Research Gap**）：指出海量誤報與良性告警導致分析師告警疲勞 43, 49, 57，且五種主流 LLM Agent 推理策略在告警調查中漏判率高達 40.4% 以上 43, 50, 54，同時過高的自動化容易引發分析師的自動化自滿 43, 50, 59。
- **C. Cure**（提出的解藥）：提出 **AI SOC Analyst Agent**，結合 ML 分級機率、MITRE ATT&CK 領域知識與 LLM 邏輯推理，提供有依據、可解釋且具備主動升級機制的告警分級系統 44, 49, 64。
- **D. Development**（方法設計）：以 ReAct LLM 進行任務規劃 44, 80, 128，結合 Gradient Boosted Trees（GBDT）預測 TP/BP/FP 機率並由 SHAP 提供特徵解釋 44, 83, 131，利用 Chroma 檢索 ATT&CK 知識與 NIST SP 800-61 Rev. 3 流程 44, 83, 84，並經由證據融合模組實現安全升級 44, 85, 92, 144。
- **E. Experiments**（實驗規劃）：採用 Microsoft GUIDE（100 萬起真實事件 45, 53, 94）與 ExCyTIn-Bench 45, 55, 94，比對多數類別、歷史誤報率規則、純 GBDT 與純 LLM 基線 45, 95, 147，評估 Macro-F1、TP 漏判率與人工升級率 45, 95, 147。
- **F. Findings / Expected Outcomes**（預期成果）：預期能顯著降低 TP 漏判率，將漏判率與升級率的取捨關係量化呈現，並產出附帶證據鏈的高可解釋性報告 45, 68, 95, 96。

### 2. Introduction 緒論（A–F 結構與問題定義）13, 14

- **A. Attention Getter & B. Background**：說明國安局與 Mandiant M-Trends 2026 數據（攻擊者潛伏時間中位數 14 天 46, 66），並說明 SOC Tier-1/Tier-2 分級流程（TP/BP/FP）47, 110, 111 及與 AIoT/OT 環境欠缺端點防護的關聯性 48。
- **C. Problem**：明確定義核心研究問題：「能否設計一個 AI Agent，結合 ML、資安領域知識與 LLM 推理，對資安事件提供有依據、可解釋，並且知道何時該交給人的分級與處置建議？」49, 126。
- **D. Existing Limitations**：歸納現有方法的五大不足：ML 缺乏攻擊鏈脈絡 50、LLM 漏判率高且易過早結案 50, 54、領域知識未明確整合 50、缺少人機協作驗證機制 50, 70 以及評估難以重現 50, 57。
- **E. Innovation**：製作對照表，從判斷方式、領域知識、不確定性處理、證據不足處置、可解釋性、評估維度與最接近研究（AIDA）對比等 7 個面向展示創新 51, 64。
- **F. Contributions**：條列系統、方法（Algorithm 1、2 52, 89, 92）、實驗、領域研究與可重現性／交接（Final Handover）等 5 大技術貢獻 52。

### 4. Deep Research（三大核心問題深度探討）20-25

**Q1. 五個核心思維模式（Mindsets）** 20, 21, 65-70：

1. **M1 Assume Breach**：假設已遭入侵，「查無紀錄」不等於無攻擊，引導 Agent 擴大查詢而非直接結案 65, 66。
2. **M2 事件與攻擊鏈脈絡**：以 Incident 為分析單位，追蹤 ATT&CK Tactic 推進階段 67。
3. **M3 錯誤成本不對稱**：漏判（FN）代價遠高於誤報（FP），系統設計偏向安全升級 68。
4. **M4 看 TTPs 而非 IOCs**：以 Pyramid of Pain 為基礎，注重攻擊行為特徵避開 IP/Hash 捷徑 69。
5. **M5 自動化要可驗證**：每一項結論附帶完整證據鏈，由分析師保留最終審查權 70。

**Q2. 三個專業爭論（Controversies）** 22, 23, 71-76：

1. **全自動 AI SOC ↔ 人機協作**：主張人機協作，以 ML 處理高信心事件，高風險或不確定事件主動升級 71, 72。
2. **規則式偵測 ↔ 機器學習**：採用混合架構，GBDT 提供機率預測，Kill Chain 規則設定硬性約束 73, 74。
3. **公開資料集能否代表真實 SOC**：採用 GUIDE 與 ExCyTIn-Bench 交叉驗證，並依事件與組織切分資料防止資料洩漏 75, 76。

**Q3. 十個深度理解問題（Deep Questions）** 24, 25, 77, 114：設計 10 題涵蓋 Why, What-if, Trade-off, Failure Case, Evidence, Comparison, Design Decision, Real-world Scenario 的深度推理解答。
